fl-legal-v3 · Fastify / Node.js · Firebase RTDB · v1.0.0

Introduction

Overview

This document describes the REST API powering the fl-legal-v3 platform — the public website and internal management tool for Fric, Lowenstein & Co. LLP. The API is a Fastify application deployed as a Vercel serverless function, backed by Firebase Realtime Database.

All endpoints are served from the same origin as the Angular client. In production, apiURL is the empty string '' (same-origin); all route strings include the /api segment explicitly.

Base URL (production): https://fl-legal.ca
Base URL (local dev): https://localhost:8228
Example request
curl -X POST https://fl-legal.ca/api/auth/editor \
  -H "Content-Type: application/json" \
  -d '{"password":"your-editor-password"}'

Authentication

Security

Two independent JWT bearer schemes are in use. Tokens are issued by the auth routes and must be sent on all protected requests as an Authorization: Bearer <token> header.

Editor JWT

Issued to the firm secretary via password authentication. Grants write access to all CMS content routes. Default expiry: 4 hours.

POST /api/auth/editor

Lawyer JWT

Issued to lawyers via Firebase ID token exchange or username/password. Grants access to calendar routes. Default expiry: 8 hours.

POST /api/auth/lawyer
POST /api/auth/lawyer/password
Using a token
# All protected routes require this header
Authorization: Bearer eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...
Token storage (Angular client): Editor tokens are stored in sessionStorage under the key fl_editor_token. Lawyer tokens are stored in sessionStorage under fl_lawyer_token. Neither is persisted to localStorage.

Rate Limiting

Security

Auth endpoints are rate-limited per IP. Exceeding the limit returns 429 Too Many Requests. Content and calendar routes inherit the Fastify global rate limiter defaults.

Endpoint Limit Window
POST /api/auth/editor 10 requests 15 minutes
POST /api/auth/lawyer 20 requests 5 minutes
POST /api/auth/lawyer/password 10 requests 15 minutes

Error Format

Conventions

All error responses return a JSON object with a single error string. Error messages are intentionally vague on auth routes to avoid credential enumeration. 

// 401 Unauthorized
{
  "error": "Invalid credentials."
}

// 403 Forbidden
{
  "error": "Editor access required."
}

// 429 Too Many Requests
{
  "error": "Rate limit exceeded, retry in 15 minutes."
}

Auth

Token issuance
POST /api/auth/editor Secretary login ▾

Validates the submitted password against the bcrypt hash stored in the EDITOR_HASH environment variable. Returns a signed JWT on success. The response token should be saved to sessionStorage and sent as Authorization: Bearer on all subsequent CMS write requests.

Public route — no Authorization header required. Rate-limited to 10 attempts / 15 min / IP.
Request body
FieldTypeConstraintsDescription
passwordrequired string 1–256 chars The shared editor password
Example request
POST /api/auth/editor
Content-Type: application/json

{
  "password": "your-editor-password"
}
Responses
200
{ "token": "eyJ..." } — JWT valid for 4 hours by default (EDITOR_TOKEN_EXPIRY env var).
401
{ "error": "Invalid credentials." }
429
Rate limit exceeded.
Changing the password

Use auth-cli.sh option 7 — Generate bcrypt hash, then update EDITOR_HASH in both server/.env and the Vercel environment variable dashboard. No redeploy is required for Vercel env var changes if the function is reinvoked (cold start picks up the new value).

POST /api/auth/lawyer Firebase ID token exchange ▾

Accepts a Firebase ID token obtained client-side via the Firebase Auth SDK and exchanges it for an API JWT. This decouples downstream calendar routes from Firebase Admin SDK validation — all subsequent requests use only the issued API JWT.

Public route — no Authorization header required. Rate-limited to 20 attempts / 5 min / IP.
Request body
FieldTypeConstraintsDescription
idTokenrequired string minLength: 1 Firebase ID token from the client-side Auth SDK
Responses
200
{ "token": "eyJ..." } — JWT valid for 8 hours by default (LAWYER_TOKEN_EXPIRY env var).
401
{ "error": "Invalid or expired Firebase token." }
429
Rate limit exceeded.
POST /api/auth/lawyer/password Username + password login ▾

Alternative lawyer login. Reads /lawyers/{username} from Firebase RTDB, compares the submitted password against the stored bcrypt hash, and returns the same API JWT as the Firebase ID token exchange route. Lawyer records are seeded from firebase-calendar-seed.json.

Public route — no Authorization header required. Rate-limited to 10 attempts / 15 min / IP.
Request body
FieldTypeConstraintsDescription
usernamerequired string minLength: 1 Lawyer's username key in RTDB, e.g. bill.fric
passwordrequired string minLength: 1 Lawyer's plain-text password (compared against passwordHash)
Known lawyer usernames
// Firebase RTDB path: /lawyers/{username}
bill.fric        // William H. Fric — Partner
howard.lowenstein // Howard M. Lowenstein — Partner
anthony.dilello  // Anthony J. Di Lello — Associate
tami.fric        // Tami Fric — Associate
york.campbell    // York Campbell — Associate
marc.lowenstein  // Marc A. Lowenstein — Associate
Responses
200
{ "token": "eyJ..." }
401
{ "error": "Invalid credentials." }
429
Rate limit exceeded.
500
{ "error": "Login failed. Please try again." } — Firebase read error.
Changing a lawyer password

Use auth-cli.sh option 7 — Generate bcrypt hash, then write the resulting hash to /lawyers/{username}/passwordHash in Firebase RTDB directly via the Firebase console or a seeding script.

Content

CMS — editor-protected writes

Site content is stored in Firebase RTDB under public/siteContent/{key}. Read operations are public; write operations require a valid Editor JWT. All writes go directly to RTDB via SiteService, bypassing the HTTP layer on the Angular side — these API routes are the server-side counterpart.

Known content keys: home, aboutUs, areasOfLaw, faq, pricing.

GET /api/content/:key Read a content node ▾
Public route — no Authorization header required.
Path parameters
ParameterTypeDescription
keyrequired string Content node key — e.g. home, aboutUs, pricing
Responses
200
The content object for the requested key.
404
{ "error": "Content not found." }
PUT /api/content/:key Update a content node ▾
Editor JWT required — Authorization: Bearer <editor-token>
Path parameters
ParameterTypeDescription
keyrequired string Content node to update
Request body

Partial or full content object. Merged shallowly into the existing node via dbUpdate().

Responses
200
{ "ok": true }
401
Missing or invalid editor token.
403
Token present but not an editor role.

Calendar

Lawyer-protected

Calendar events are stored in Firebase RTDB under public/calendar. All calendar routes require a valid Lawyer JWT. Event type colours and status types are driven by public/calendarMeta.

GET /api/calendar List all events ▾
Lawyer JWT required — Authorization: Bearer <lawyer-token>
Query parameters
ParameterTypeDescription
lawyerIdoptional string Filter events by lawyer UID, e.g. lawyer-bill-001
dateoptional string ISO date string — filter to a specific day, e.g. 2026-04-14
Response — event shape
{
  "id":          "event-001",
  "title":       "Client Consultation — Smith Real Estate Purchase",
  "date":        "2026-04-07",       // YYYY-MM-DD
  "time":        "09:00",            // HH:mm (Calgary local time)
  "duration":    60,                 // minutes
  "type":        "consultation",     // see calendarMeta.eventTypes
  "lawyerId":    "lawyer-bill-001",
  "lawyerName":  "William H. Fric",
  "clientName":  "Robert Smith",
  "description": "...",
  "location":    "Office — Suite 750",
  "status":      "confirmed",        // confirmed | pending | cancelled
  "createdAt":   "2026-03-20T14:22:00.000Z"
}
GET /api/calendar/:id Get a single event ▾
Lawyer JWT required — Authorization: Bearer <lawyer-token>
Path parameters
ParameterTypeDescription
idrequired string Event ID, e.g. event-001
Responses
200
Single event object (same shape as list above).
404
{ "error": "Event not found." }

Inquiries

Public — client submissions

Client inquiry submissions from the public website. Standard inquiries are POSTed to /api/inquiries; priority matters (flagged in the dialog) are POSTed to /api/inquiries/priority. Both routes trigger a notification email to the firm via SMTP/SendGrid.

POST /api/inquiries Submit a client inquiry ▾
Public route — no Authorization header required.
Request body
FieldTypeDescription
namerequired string Client full name
emailrequired string Client email address
phoneoptional string Client phone number
practiceAreaoptional string Practice area of interest — e.g. real_estate, wills_estates
messagerequired string Inquiry message body
Responses
200
{ "ok": true } — inquiry received and email dispatched.
400
Validation error — missing required fields.
500
SMTP dispatch failure.
POST /api/inquiries/priority Submit a priority inquiry ▾
Public route — no Authorization header required.

Identical body shape to POST /api/inquiries. Priority inquiries are flagged in the notification email subject line and may be routed differently by the firm's intake process.

Responses
200
{ "ok": true }
400
Validation error.
